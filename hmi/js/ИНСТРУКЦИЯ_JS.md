# Панель ГЦУ-1 на JS-объектах — как вставить в EasyBuilder Pro (версия 2.0)

Панель cMT2158X (1024×768), EasyBuilder Pro 6.10. Каждое окно — **один JS-объект** во всю рабочую
область. Его код и конфигурация — готовые файлы из этой папки: ничего не рисуется вручную.
Верхняя полоса и нижнее меню — ваше общее окно 4 (как сейчас).

## Что где

| Окно | Объект JS | Код (вкладка «Исходный код») | Конфигурация («Шаблон…») |
|---|---|---|---|
| 10 или 16 — Мнемосхема | X0 Y48 1024×664 | `gcu_mimic.js` | `config_mimic.json` |
| 11 — Насос 1 | X0 Y48 1024×664 | `gcu_pump.js` | `config_pump1.json` |
| 12 — Насос 2 | X0 Y48 1024×664 | `gcu_pump.js` (тот же) | `config_pump2.json` |
| 13 — Регуляторы | X0 Y48 1024×664 | `gcu_settings.js` | `config_settings.json` |
| 14 — Аварии | X0 Y48 1024×664 | `gcu_alarms.js` | `config_alarms.json` |
| 15 — Тренды | X0 Y48 1024×664 | `gcu_trends.js` | `config_trends.json` |
| **17 — Входы/выходы** (новое) | X0 Y48 1024×664 | `gcu_io.js` | `config_io.json` |
| **18 — Пульподелитель** (новое) | X0 Y48 1024×664 | `gcu_pd.js` | `config_pd.json` |
| **4 — общее окно**: регистратор | маленький, напр. X1000 Y4 20×20 | `gcu_recorder.js` | `config_recorder.json` |

Регистратор невидим. Он всё время пишет тренды (каждые 5 с, 8 часов) и журнал аварий/событий
в память панели (MemoryStorage). Окна «Тренды» и «Аварии» показывают эту историю.
После перезагрузки панели история начинается заново.

## Шаг 0. ПЛК (только для окна «Входы/выходы»)

В `plc/5_GCU_HMI.scl` добавлены DB `HMI_IO` и FC `GCU_HMI_IO`, вызов — в `GCU_Main`.
1. Импортируйте `plc/5_GCU_HMI.scl` заново (как обычно, последним).
2. Свойства DB `HMI_IO` → General → Number: **102** (вручную, как DB100/101).
3. Compile → Software (rebuild all), загрузите в ПЛК.

Остальные окна работают и без этого шага.

Для окна 18 (пульподелитель) нужны `plc/4b_PulpDivider.scl` (импорт перед `5_GCU_HMI.scl`) и номер DB `HMI_PD` = **103**.

## Шаг 1. Для каждого окна из таблицы

1. Откройте окно (11, 12, 13…; окно 17 создайте: «Входы/выходы», общее окно 4).
   Удалите из окна старые объекты, если они там есть (или сначала попробуйте в копии окна).
2. **Объекты → JavaScript → JS-объект**, поставьте и задайте профиль из таблицы.
3. Вкладка **«Исходный код»**: вставьте файл кода целиком → «Компиляция» (ошибок быть не должно).
4. Вкладка **«Конфигурирование»** → **«Шаблон…»** → удалите всё → вставьте файл конфигурации → OK.
5. OK, сохранить.

Для окна 17 добавьте в меню или в окно 13 функциональную кнопку «Сменить базовое окно → 17».

## Шаг 2. Проверка

- **Офлайн-симуляция**: в «Шаблон…» поменяйте `"demo": false` на `true` — увидите окно с имитацией
  (жёлтая плашка «ДЕМО-РЕЖИМ»), всё нажимается. Потом верните `false`.
- **С ПЛК**: окна сразу показывают реальные данные. Проверено на стенде: DB100/DB101 читаются верно.

## Окна — что в них

**Насос 1/2** — шаги последовательности с подсветкой текущего, код аварии; частотник (состояние,
дистанция/местное, задание, пуски, ручное задание, ПУСК/СТОП/СБРОС — только в РУЧНОМ, аварии ПЧ);
6 задвижек развязки с ОТКР/ЗАКР (нажатие на название — окно задвижки); «основной», «в ремонт».

**Регуляторы и уставки** — все поля DB101 с теми же пределами, что проверяет ПЛК; ремонт ГЦ и насосов,
основной насос. Пароль инженера: в конфигурации `"pin": "1234"` (пусто — без пароля); доступ на 10 минут.

**Аварии** — АКТИВНЫЕ (время появления, мигание неквитированных), ЖУРНАЛ (появилось/ушло/квитировано,
события режима, пуска, АВР, местного управления, действия оператора, изменения уставок).
КВИТИРОВАТЬ, СБРОС АВАРИЙ (ГЦУ, линии Н-1/Н-2 и задвижки с аварией).

**Тренды** — уровень, давление, скорость насоса; 15 мин / 1 ч / 8 ч; пауза и прокрутка; уставки пунктиром.

**Входы/выходы** (по стандарту предприятия, без графиков) — вкладки DI/DO/AI/AO, выбор ID (◀ ▶ и список
всех сигналов с адресами), все параметры структуры `TDIData/TDOData/TAIData/TAOData`:
серые — только чтение, белые — правка (клавиатура), кнопки ВКЛ/ВЫКЛ — признаки (маска, использование уставок,
инверсия, активность…). Маскирование, активность, деактивация алармов — с подтверждением.
Справа — «Сигнализации» и «Управление сигналом». Пароль инженера — `"pin"` в `config_io.json`.

Как работает: панель пишет в DB102 тип и ID, ПЛК копирует `Item[ID]` в буфер; правка уходит командой
«код поля + значение», ПЛК меняет одно поле и отвечает счётчиком `Ack` («ПЛК принял изменение»).
Сигнальные DB панель целиком не перезаписывает.

**Пульподелитель** — схема (питание → делитель → задвижки №1–3 → зумпф мельницы 1 / зумпф мельниц 2 и 3),
для каждой задвижки: состояние, концевики, время движения и две кнопки **▲ ОТКРЫВАТЬ / ▼ ЗАКРЫВАТЬ, которые действуют,
пока нажаты**. Отпустили — задвижка остановилась. Сама остановится на концевике и через «макс. время непрерывного движения»
(по умолчанию 30 с, меняется в окне). При потере связи с панелью ПЛК снимает выход через 0,7 с.

## Как окна получают данные (версия 2.2)

- **Подписок нет совсем.** JS-объект не запускает код, пока не ответят все его подписки, — без связи с ПЛК окно осталось бы пустым.
  Поэтому все данные окна **опрашивают сами** через записи «Адрес» (они запуск не блокируют):
  `cmdAddr` → DB100.0…187 (0,5 с), `setAddr` → DB101 (2 с), `extAddr` → DB100.188…207 (1 с), `ioAddr` → DB102 (0,5 с), `pdAddr` → DB103 (0,25 с).
- **Нет связи с ПЛК** — все окна открываются: прочерки вместо значений и красная полоса «НЕТ СВЯЗИ С ПЛК» внизу
  (на мнемосхеме — в строке аварий). Пропала связь во время работы — остаются последние значения, полоса так и пишет.
- Нет блока DB102/DB103 в ПЛК — окно открывается и пишет «нет данных».
- Пароль инженера: по умолчанию нет. Включить — в «Шаблон…» добавить строку `"pin": "1234",` (свой пароль).

## Если что-то не так

| Симптом | Что делать |
|---|---|
| Ошибка при «Компиляция» | скриншот мне |
| После «Шаблон…» записей меньше, чем в файле | пришлите текст из «Шаблон…» |
| «Чтение данных сигнала…» в окне 17 не проходит | DB102 не загружен / номер не 102 / ПЛК без `GCU_HMI_IO` |
| В трендах «Нет записанных данных» | нет регистратора в общем окне 4, или прошло < 5 с |
| Квадратики вместо букв | `"fontFamily"` — другой шрифт |
| Окно пустое (ничего не рисуется) | вставлена старая конфигурация с подпиской на DB102/DB103 или на DB100 длиннее 100 слов — вставить новый `config_*.json` |

## Для разработчика

Новые окна удобнее делать в конструкторе: `hmi/constructor/Конструктор_панели.html` (тот же `core.js`; после правки ядра — `python hmi/constructor/build.py`).


Исходники — `src/`: `core.js` (общее: разбор DB, запись, кнопки, клавиатура, окна, журнал, пароль)
и `scr_*.js` (экраны). Сборка: `python hmi/js/src/build.py`. Эмулятор API Weintek — `test_harness.html`.
Адреса в конфигурации — base64 в формате EasyBuilder (устройство «Siemens S7-1200/S7-1500», DBn, адрес, длина).
