# Окна «Аварии», «Тренды», «Входы/выходы» в конструкторе: что перенесено и чего не хватает

Генераторы: `src/make_alarms.js` (экран `al_s1`), `src/make_trends.js` (`tr_s1`), `src/make_io.js` (`io_s1`, `io_s2`; DB `HMI_IO` = DB102).
Каждый возвращает `{ screens, pops, dbs }` для `make_all`. Проверка размера/тегов: все четыре экрана экспортируются без предупреждений
(77 / 63 / 93 / 90 КБ кода при лимите ~100 КБ).

## Аварии (окно 14, scr_alarms.js)
Перенесено: заголовок, легенда, **активные** тревоги — элемент «Список сообщений» по тем же условиям, что `alarmList()` ядра (15 бит DB100 без «АВР»,
аварийные стопы, гидроподпор, 6 флагов ПЧ ×2, ремонт насосов, 4 флага ×18 задвижек, ремонт ГЦ), сортировка «аварии выше»; причина остановки линии
(код → текст) отдельными строками; «ЗВУК ВКЛ»; КВИТИРОВАТЬ (команда ГЦУ 8); СБРОС АВАРИЙ (resetall с подтверждением).

| В оригинале | В конструкторе | Что добавить в движок |
|---|---|---|
| Вкладка «ЖУРНАЛ» (события из регистратора, MemoryStorage, 8 ч) | нет | элемент «Журнал событий» (хранилище + фиксация появления/ухода условий) или регистратор как отдельный объект |
| Время появления, колонки «Время/Тип/Состояние» | нет (только цветная метка, текст) | в `alarms`: время появления условия, колонки, «Квитировано» по строке |
| Постраничный вывод ▲▼ (13 строк) | список ограничен высотой (12 строк, «ещё N») | пейджер или прокрутка у `alarms` |
| Счётчик «АКТИВНЫЕ · N» на вкладке | нет | счётчик активных элементов `alarms` как значение |
| Условие «код = значение» (FAULT_TEXT по `faultCode`) | отдельные `value` с «текстом по значению» | условие `op/v` у пунктов `alarms` (сейчас пункт — только бит/инверсия) |
| Мигание непринятых, фон строки предупреждений | у `alarms` цвет полоски, нет фона | фон строки по категории |
| Звук квитируется и локально (`localSeen`) | КВИТИРОВАТЬ шлёт 8 в ПЛК (доступно только при данных ГЦУ) | — |

Теги, которых нет в списке встроенных `gcu:` редактора (красная рамка в редакторе, но ядро их читает — путь в `S`): `gcu:alm2.sealBad.1/2`,
`gcu:pump.N.fltStart/fltStop/fltUnxStart/fltUnxStop`, `gcu:valve.N.fltTravel/fltLimits/fltSwitch/fltSignal`, `gcu:set.levelSP/pressSP`.
→ добавить их в `GCU_TAGS` (editor.js), иначе в «Выборе тега» не видны.

## Тренды (окно 15, scr_trends.js)
Перенесено: две панели «Тренд» (уровень + уставка + скорость в %; давление + уставка в барах), карточки «Сейчас» с уставками, число циклонов, рабочий насос.

| В оригинале | В конструкторе | Что добавить в движок |
|---|---|---|
| История из регистратора: 8 ч, пишется всегда (окно 4) | история копится только пока открыто окно, 1 с/точка, окно 1 ч | фоновый регистратор (отдельный объект/опция проекта), хранилище 5 с/8 ч |
| Переключатели 15 мин / 1 ч / 8 ч | фиксировано 1 ч | `span` по тегу/переменной окна или группа кнопок «видимость по состоянию» с локальной переменной UI |
| ◀ ❚❚ ▶ прокрутка и пауза | нет | ось времени у `trend` с паузой/сдвигом |
| Две шкалы на одном графике (% слева, бар справа) | два графика друг над другом | вторая ось у `trend`: перо с собственным min/max |
| Уставки пунктиром | отдельные перья другого оттенка | стиль пера (пунктир) |
| Подписи времени по оси X (чч:мм) | «−N мин … сейчас» | метки времени у `trend` |

## Входы/выходы (окно 17, scr_io.js + io_signals.js, DB102 HMI_IO)
Один объект не помещается в лимит (ядро + 4 набора параметров ≈ 118 КБ), поэтому два экрана: `io_s1` (DI/DO) и `io_s2` (AI/AO).
Вкладки «своей» части пишут `HMI_IO.Kind`, вкладки другой части — действие «Перейти в базовое окно» (по умолчанию 19 ↔ 17: поправьте номера
в кнопках и задайте `winAddr` экрана; при открытии окна другой части нужно нажать её вкладку, чтобы выставить Kind).
Перенесено: вкладки, заголовок, ID (поле ввода) + имя сигнала (все 99/44/… названий из `io_signals.js` как «текст по значению» от `Id`), поля параметров всех 4 видов,
панель «Сигнализации» (лампы), «Управление сигналом».

| В оригинале | В конструкторе | Что добавить в движок |
|---|---|---|
| Правка одним запросом `[Kind, Id, Cmd, CmdVal]` | **двухшагово**: значение в `CmdVal` (поле вверху справа, «= 1», «= 0»), затем кнопка ▶ в нужной строке пишет `Cmd` | действие `seq`/«несколько записей» (список `{tag, v | введённое значение}`) и «ввести число и записать в Cmd» |
| Значение Bool-тумблера = `!текущее` | оператор сам выставляет «= 1»/«= 0» | действие «инвертировать текущее и записать в Cmd/CmdVal» |
| ◀ ▶ перебор ID, список сигналов в окне выбора | только ввод номера | действие `inc/dec` для тега с пределами, окно выбора из списка (openList) |
| Пределы ID по виду (MaxId) | поле ввода 1…99 (ПЛК игнорирует лишнее) | пределы поля ввода из тега |
| `ioValid()` — защита от чужого буфера, «Чтение данных…» | нет | условие «Kind и Id совпадают» как условие видимости |
| Адрес `%I32.4` у DI/DO только в имени сигнала | байт и бит показаны числами | форматирование «%I{байт}.{бит}» |
| «не исп.» вместо −1 у статусных байт/бит | число −1 | «текст по значению» с диапазоном |
| Пароль инженера (`cfg.pin`) | у полей/кнопок правки включён «пароль»; сам PIN задаётся в свойствах окна | — |
| Журнал события при правке (`logEvent`) | не пишется (убрано ради размера) | — |
| Демо-режим (`demoIoBuild`) | в ▶ Просмотре память имитатора ПЛК: пустые поля; несколько значений для DI 1 / AI 1 заданы | имитатор HMI_IO |

Размер: каждый набор параметров — отдельная группа с условием видимости по `Kind`; повторяющиеся стили элементов увеличивают код.
Облегчить можно «наследованием» стилей элемента (общие свойства `fill/stroke/r/size` один раз на группу) — это и дало бы объединить две части обратно.
